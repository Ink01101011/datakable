- A new `data` array on a searched table no longer matches the query against every row again: each row's searched text is hashed, and only rows whose text changed since the last search (compared at the same position, or shifted by an insert or a delete) are matched; the others keep their score. Row identity is not used, so a row changed in place and passed in a new array is matched again. A one-row `setData` with a search applied at 100k rows went from about 57 ms to about 19 ms; a new query on the same data hashes nothing. A changed row keeps a stale score only on a 53-bit hash collision (at most 2·2⁻⁵³ per changed row). The kept hashes and scores take 16 bytes per row. (#95)
