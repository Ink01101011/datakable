# D1 — How to use guides (plan)

Job datakable-docs-v1, unit D1, branch `feat/core-D1` from `feat/core-V1` (5160236).

## Goal

Write `docs/how-to-use/`: one guide per concept or feature of the 1.0 API, each with purpose, how it
works, a full options / API table read from the TypeScript types, compiled examples, pitfalls
(linking the diagnostics reference) and See also. Update `docs/how-to-use/README.md`.

## Pages

getting-started, core-concepts, state, columns-and-row-keys, features, column-filters, search,
sorting, pagination, validity, server-mode, schema-validation, react, ssr, diagnostics,
custom-features-and-interceptors, performance, entry-points.

## Method (test-first)

1. The tests already exist (V1): `docs-examples.test.ts` (each ```ts / ```tsx block equals its file
   under `packages/datakable/src/docs-examples/how-to-use/<page>/<n>-<slug>.ts(x)`, and every file
   is shown) and `docs-links.test.ts` (every link and anchor resolves; every page reachable).
   The README index links every page first, so both tests fail until the pages exist.
2. Per page: read the source and types, write the example files, `biome check --write` them,
   `pnpm --filter datakable typecheck`, then copy the files into the page blocks (scratch sync
   script) and write the prose and tables around them. Runtime claims are checked against the
   built packages with scratch scripts.
3. Gate: `pnpm lint && pnpm build && pnpm typecheck && pnpm test && pnpm check:pkg &&
   pnpm check:budgets`.
