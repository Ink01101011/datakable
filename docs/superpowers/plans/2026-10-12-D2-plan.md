# D2 — Examples cookbook: plan

Job datakable-docs-v1, unit D2 (implementer), branch `feat/core-D2` from `feat/core-V1`.

## Goal

`docs/examples/` becomes a cookbook of task-oriented recipes. Each recipe page: title, one paragraph
on what it is for, the goal, the full code (compiled example files), what you will see, variations
and "See also" links. Every ```ts / ```tsx block is a file of
`packages/datakable/src/docs-examples/examples/<page>/<n>-<slug>.ts(x)` (V1 drift test), compiled
by `pnpm typecheck` against the built packages.

## Recipes

| Page | Recipe |
| --- | --- |
| `zero-config.md` | `<DataTable data />` from an array; the same table headless with `createTable` |
| `custom-columns.md` | headers, `format`, `cell` renderers, dot-paths, a derived column, `sensitive` |
| `headless-table.md` | `useDataTable` with your own markup: search, a column filter, sort headers, pager |
| `server-side-table.md` | `fetcher` + loading / error / retry UI from `status` + `isInitialLoad` |
| `async-search.md` | `withSearchFn` over a search API, debounced typing |
| `schema-validation.md` | Standard Schema, `invalidRows: 'flag'`, a "show invalid" toggle |
| `url-state.md` | controlled sorting / search / page synced with the query string |
| `nextjs-ssr.md` | Next.js app router: server component fetches, client `<DataTable initialData />` |
| `row-selection-feature.md` | a custom feature (`defineFeature`) with a typed API |
| `logging-interceptor.md` | a custom interceptor (`defineInterceptor`) for analytics / timings |
| `error-reporting.md` | `onDiagnostic` → a Sentry-style reporter with redaction |
| `theming.md` | `datakable/styles.css`, `--dk-*` variables, dark mode |
| `large-data.md` | 100k rows: stable inputs, pagination, search weights, sort algorithm |

## Tests (test-first)

- The V1 drift and link tests cover the pages (blocks == files, links resolve, pages reachable).
- New smoke test `packages/datakable/src/docs-examples/examples/_recipes.test.tsx` (`_` = helper,
  not shown) imports each recipe and runs it: renders the React recipes with
  `@testing-library/react` (happy-dom), asserts what the page says you will see; runs the headless
  ones; the Next.js page through `react-dom/server`. `datakable` is mapped to the package source
  with `vi.mock`, so `pnpm test` needs no build.

## Out of scope

- `docs/how-to-use/**` (D1), `docs/how-to-fix/**` (D3), the hub `docs/README.md` (V1 / RD).
- Links to D1 / D3 pages that do not exist on this branch: listed in the report for RD.
- Any library code change; vitest / tsconfig changes.
