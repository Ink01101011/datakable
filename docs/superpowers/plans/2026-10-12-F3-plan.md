# F3 — core `createTable` toward ≤ 8 KB gzip (§9.3)

Job `datakable-core-v1-budgets`, unit F3. Baseline (develop c43948f, `pnpm size`): core `createTable`
**23,535 B** gzip (63,229 B min). Spec changes approved by the user on 2026-10-13 (brief F3).

## Design

1. **Option validation is DEV-only** (§3.4 `optionValidator`). `validateOptions` /
   `validateOptionChange` (catalog validator, table-options schema, `suggest`) run behind `DEV`.
   Production keeps the one check needed for correctness: `setOptions` keeps the previous value of
   every read-once option (`READ_ONCE`, a constant list; a test pins it to the catalog's `once`
   rules).
2. **Drop the `merge` sort algorithm** (§6.4): `tim | radix | counting | native | fn` remain.
3. **Schema is an opt-in import** (§5.1): `schema: withSchema(UserSchema)` from
   `@datakable/core/schema`. The wrapper is the same Standard Schema (types unchanged: `T` from its
   output, `Row<T>` flag-mode union) plus a hidden installer; memoised per schema, so an inline call
   in a React render keeps one identity. A raw schema is a compile error, and in DEV a
   `DK_INVALID_OPTION` naming the wrapper.
4. **Server source is an opt-in import** (§7.1): `fetcher: withFetcher(fetchUsers)` from
   `@datakable/core/server`. `fetcher` stays a (dynamic) option, so `setOptions({ fetcher })`, the
   React sync and `DK_UNSTABLE_OPTION` keep their behaviour; the wrapper is memoised per function.
   The request machinery (asyncControl, in-flight status, settle batching, SSR deferral) moves out
   of `createTable` into a lazily created table extension shared by the fetcher and `searchFn`.
5. **Internal extension seam** (`table/internals.ts`): `internals.use(factory)` creates one
   extension per table; extensions contribute a status (precedence §6.6), a flush hook and
   interceptors placed first in the chain. Not public API.
6. Then measure and move further dead weight of a bare table behind DEV or its feature/entry
   (versioning registry, data checks, mode-order check, …), keeping spec-required prod behaviour
   (`explain` stays in prod).

Every step: `pnpm build && pnpm size`, numbers in the commit message; ratchets lowered to the
measured value rounded up to 0.5 KB.

## Call sites

`packages/react` (`useDataTable` / `DataTable` pass `fetcher` / `schema` through — types only),
`packages/datakable` (preset unchanged; README examples), docs (`errors.md` examples, READMEs),
spec sections marked "changed 2026-10-13 for §9.3".
