## Floating-promise decision

Biome 2.5.15 (lockfile) ships `lint/nursery/noFloatingPromises` (available since 2.0.0, domain
`types`, default severity info; not enabled by the `recommended` preset). Probe fixture
`packages/core/src/__fp_probe/{helper,probe}.ts` with 8 promise statements, 7 floating:
local async fn, imported async fn, imported promise-returning arrow, `Promise.resolve()`,
`new Promise()`, `.then()` with one arg, a class method via `this`. The handled one
(`const p = load()`) was not reported.

Result: `biome lint` reported all 7 (`probe.ts` lines 8, 9, 10, 11, 12, 14, 22; "Found 7
errors") and `pnpm lint` exited 1. Fixture removed; `pnpm lint` clean again. **Decision:**
enable `linter.rules.nursery.noFloatingPromises: "error"` in `biome.json`; no test-based check.

Risk: nursery rules may change or be promoted between biome minors (`^2.5.15`). If an upgrade
renames it, `biome check` fails on the unknown key, so the break is visible.
