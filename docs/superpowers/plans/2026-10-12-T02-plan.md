# T02 — Column types: implementation plan

**Goal:** port the brainstorm column-type prototypes (`proto.ts`, `anyp.ts`) into
`packages/core/src/column/` with the §4.2 loose-type fixes, and pin every prototype case as a
`*.test-d.ts` type test.

**Spec:** §4.1 (`ColumnDef<T, R>`), §4.2 (loose types).
**Branch / worktree:** `feat/core-T02` at `/Users/kktest/Projects/datakable-wt/T02`.

## Steps

1. Write the three `*.test-d.ts` files first, driving a test-local `declare function table(...)`
   shaped like the prototype `useDataTable` signature. Run `pnpm test` — expect failures (module
   missing).
2. Port `proto.ts` types verbatim into `path.ts` / `column-def.ts`.
3. Add §4.2 handling: `IsAny<T>`; whole-row `any` → `Record<string, unknown>`; `any` / `unknown`
   values need no `cell` / `format`; loose filter kinds (`equals`, `contains`) for them.
4. Add the remaining §4.1 fields: `sortFn`, `sortBy`, `sortAlgorithm`, `sensitive`, `invalidCell`.
5. Mutation check: temporarily widen `Path` to `string` and confirm `@ts-expect-error` lines go
   unused; revert.
6. Measure `tsc --extendedDiagnostics` on the column module vs spec (0.26 s / 29,838).
7. Gate: `pnpm lint && pnpm build && pnpm typecheck && pnpm test`. Commit.

## Out of scope

- `getValue()` and the default formatter (T03).
- Object-column `sortable` requiring `sortFn` / `sortBy` (T14 owns that type test).
- Filter value shapes and `custom` filters (T13); `FilterFor` keeps the prototype `{ type }` shape.
- `rowKey` as a function, zero-config column derivation (T11, T12).
- `Row<T>` invalid-row union and the final `invalidCell` context (T22 / T23); a placeholder
  context type is used.
- Pinning compiler error *messages* (§4.3 / §11) — needs a compiler-API harness; not a T02 deliverable.
- Changes to `@datakable/react` (`useDataTable` still uses `RowData`).
