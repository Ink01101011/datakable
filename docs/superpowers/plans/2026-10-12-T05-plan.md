# T05 — Diagnostics: implementation plan

**Goal:** the diagnostic model (§8.1), the `defineDiagnostic` catalog (§3.5) and the
`diagnostic:emit` chain (§8.2: enrich → redact seam → dedupe/rate-limit → sinks → ring buffer) in
`packages/core/src/diagnostics/`, plus the wave-0 carry-over fixes in `intercept/`.

**Done when:** bigint/cycle-safe `toJSON`; dedupe aggregates `occurrences`; ring buffer bounded at
100; every diagnostic carries `context.table`, `trigger` and `run` (tested).

## Files

| File | Responsibility |
|---|---|
| `diagnostics/types.ts` | `Diagnostic`, `Location`, `DiagnosticContext`, `Trigger`, `Phase`, `Emit`, `EmitOptions` |
| `diagnostics/catalog.ts` | `DiagnosticCatalog` (code → details, open to declaration merging), `defineDiagnostic`, lookup |
| `diagnostics/codes.ts` | codes T05 introduces: `DK_INTERCEPTOR_FAILED`, `DK_HOT_INTERCEPTOR`, `DK_OPERATION_CONFLICT`, `DK_INTERNAL` (minimal; T06 extends) |
| `diagnostics/safe-json.ts` | safe serializer (bigint, cycles, Errors, Map/Set, typed arrays, functions) |
| `diagnostics/build.ts` | builds a `Diagnostic` from a code + details + context (enrich, `where` text, fingerprint, docs URL); `DatakableError`, `DatakableConfigError`, `configError()` |
| `diagnostics/ring-buffer.ts` | bounded ring buffer |
| `diagnostics/console.ts` | console sink (dev group per code, prod error-only, rate limit) |
| `diagnostics/hub.ts` | `createDiagnostics()`: per-table emitter running `diagnostic:emit` through the interceptor runtime |
| `diagnostics/env.ts` | `DEV` flag (`process.env.NODE_ENV !== 'production'`) |
| `diagnostics/index.ts` | barrel (+ module docs on how to add a code and emit it) |

`intercept/` edits: `ContextBase.emit` typed as `Emit`; `diagnostic:emit` input typed as
`{ diagnostic: Diagnostic }`; runtime gets an `emit` option — hot warnings (`DK_HOT_INTERCEPTOR`, dev
only) and interceptor failures (`DK_INTERCEPTOR_FAILED`) go through it; the hot check moves into
`compile()` (warn once per interceptor + op per runtime), so ops registered after runtime creation are
checked; the `TODO(T05)` throws become `DatakableConfigError` / `DatakableError` with codes.

## Steps (test-first)

1. `safe-json.test.ts`: bigint, cycle, shared (non-cyclic) refs, Error + cause, Map/Set, typed array,
   function, non-finite numbers; `JSON.stringify` never throws.
2. `catalog.test.ts` + `types.test-d.ts`: define/lookup; duplicate code with another level throws;
   every core code builds a non-empty `where` and `fix`; `emit` rejects unknown codes / wrong details.
3. `hub.test.ts`: context (table name / `table#n`, trigger, run, phase, package); fingerprint and docs;
   dedupe aggregates and resets on a new data reference; ring buffer bounded at 100; dedupe map bounded;
   `onDiagnostic` (throwing → swallowed + one `console.error`); `strict`; console format (dev / prod);
   rate limit; user interceptor on `diagnostic:emit` can redact or drop; a throwing interceptor on
   `diagnostic:emit` does not recurse; redact seam runs; `toJSON` omits `cause`.
4. `runtime.test.ts`: hot warning for an op registered after runtime creation; once per interceptor/op
   across recompiles; `emit` option routes both codes.
5. Implement until green; gate.

## Out of scope

- Redaction levels `safe` / `keys` / `full`, `sensitive`, hashed keys (T26) — only the `redact` seam.
- `errorBoundary`, fallback registry, `DK_CALLBACK_FAILED` / `DK_UNKNOWN`, full `DK_INTERNAL` text with
  issue link (T06).
- Wiring into `createTable` (`options.name`, `onDiagnostic`, `strict`, `getDiagnostics()` on the
  table, live trigger/run/state) — store tasks (T07+). The hub takes these as options.
- `datakable/messages` opt-in for prod text, `docs/errors.md` and the catalog CI test (T38).
- Making the operation registry per table (process-global stays; see report).
