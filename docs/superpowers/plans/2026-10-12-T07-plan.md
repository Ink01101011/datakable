## Behaviour

- `getState()` returns an immutable snapshot (frozen in dev). A new snapshot only when a slice
  changes by reference; no change → no notification.
- `setState(updater)`: `updater` is a partial state or `(prev) => partial`; merged per slice. Runs
  through `state:dispatch` (`where = 'setState'`, trigger `api:setState`).
- Controlled slices: keys of `options.state` with a defined value. Their changes go to
  `onStateChange(prev => ({ ...prev, ...changedControlledSlices }))`; owned slices are committed by
  the store. Without `onStateChange`: `DK_CONTROLLED_WITHOUT_HANDLER` at init / setOptions and when
  an update to a controlled slice is dropped.
- `subscribe(listener)` → unsubscribe. Notification is a loop over a copy of the listeners, each in
  its own `try` (`DK_LISTENER_FAILED`, `where` = listener #n). Re-entrant updates from listeners are
  queued into further rounds; past `UPDATE_DEPTH_LIMIT` (50) rounds the update is dropped
  (`DK_UPDATE_LOOP`).
- `destroy()`: `table:destroy`, clears listeners; later mutating calls are no-ops with
  `DK_TABLE_DESTROYED`. Reads (`getState`, `getDiagnostics`, `getOptions`) keep working.
- Hub per table: `createDiagnostics({ name, table, onDiagnostic, strict, getContext, getDataRef,
  redaction })`; `redaction` = `{ level | redact fn from options.diagnostics.redact,
  sensitiveColumns() from column defs, rowKeySensitive() }`; runtime gets `emit: hub.emit`;
  `installBoundary(errorBoundary)`; `hub.attach(runtime)`.
- `data:ingest` sets `ctx.meta[FALLBACK]` = previous data. Seam marked for T09 (`pipeline:run` +
  last good row model).
- `ctx.where` is always a constant option path / method name — never row data (property test).
