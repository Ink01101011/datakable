# T08 — Feature contract (plan)

Spec §3.3 (feature contract), §3.1 (`feature/` module), §8.3 (`DK_FEATURE_*`). Depends on T07.

## Goal

A feature unit (waves 6+) writes one feature file with `defineFeature` and gets: its state slice in
`table.getState()`, its API merged onto the table, typed against the row type `T`, and its place
in the pipeline order. Nothing else in `createTable` needs touching.

## Steps (test-first)

1. `feature/types.ts` — port the brainstorm prototype (`typeproto/feat.ts`): `FeatureTypes`,
   `Apply`, `Feature<Name, F>`, `AnyFeature`, `StateOf`, `ApiOf`; add `Stage`, `FeatureContext`,
   `RowModelContext`, `TableStateFor` (state of a table: explicit `S` & installed slices).
   Type tests: the prototype checks verbatim (+ the `t2.selectRow({ foo: 1 })` case as
   `@ts-expect-error`), plus a no-HKT feature whose types are inferred.
2. `feature/define.ts` — `defineFeature` (identity; two overloads: HKT `<Name, Types>` and inferred
   `S` / `A`).
3. `feature/order.ts` — `STAGES` (pipeline order), `orderFeatures` (stable sort by stage) and
   duplicate detection → `DatakableConfigError` `DK_FEATURE_DUPLICATE`.
4. `feature/install.ts` — creates each API with a `FeatureContext`, detects clashes (with core table
   methods and between features) → `DK_FEATURE_API_CONFLICT`, naming both owners and suggesting a
   namespace; wraps methods (`api:<method>` trigger, destroyed → `DK_TABLE_DESTROYED`, batched
   notification).
5. `feature/codes.ts` — `DK_FEATURE_DUPLICATE`, `DK_FEATURE_API_CONFLICT` (config),
   `DK_FEATURE_FAILED` (initialState / createApi threw; `hook: 'rowModel'` reserved for T09).
6. Wire into `createTable` (T07 seams): feature `initialState()` slices under
   `options.initialState`; feature interceptors after asyncControl, before user interceptors;
   ordered features on the internals seam for T09; `features` read once at creation.
7. Extend the T07 `ctx.where` property test to feature slices / API calls.

## Out of scope

- Running `rowModel` (pipeline runner, memo, `DK_FEATURE_BAD_OUTPUT`) — T09 / T27.
- `options: defineOptions(...)` validation, `DK_UNKNOWN_OPTION` etc., runtime shape validation of a
  feature definition (unknown `stage`, missing hooks) — T10.
- `requires.core` → `DK_FEATURE_INCOMPATIBLE` — T28 (only the type is declared here).
- Per-feature `mode` and `DK_MODE_ORDER` — T21.
- The default preset (`defaultFeatures`) when `features` is omitted — the feature units / preset.
- `DK_STATE_UNKNOWN_KEY` for initialState keys — T32.
