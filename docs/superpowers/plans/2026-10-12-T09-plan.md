# T09 — Pipeline runner (plan)

Spec §6.6 (row model output), §9.1 (index pipeline, column cache), §3.3 (pipeline order, per-step
memo), §3.4 (`pipeline:run`, `pipeline:step`, `column:batch`), §8.3 (`DK_UNRENDERABLE_VALUE`).
Depends on T08 (feature contract), T03 (`getValue`, `defaultFormat`), T06 (`runCells`,
`CellFailures`), T07 (row-model FALLBACK seam).

## Goal

`table.getRowModel()` returns `{ rows, filteredCount, totalCount, status }`, computed by running the
installed features' `rowModel`s in stage order over `Uint32Array` row indices. Each step is memoised
on (input reference, own slice); `Row` objects exist only for the final (visible) indices. Features
read column values through a lazy per-data column cache.

## Steps (test-first)

1. `pipeline/codes.ts` — `DK_UNRENDERABLE_VALUE` (warn, column `where`, count + sample rows + value
   type; one report per column per data).
2. `pipeline/column-cache.ts` — `createColumnCache(host)`: `WeakMap<data, WeakMap<columnDef, entry>>`.
   `values(column)` runs one `column:batch` (slot `accessor`) over all rows with `runCells` /
   `CellFailures` (key columns: `getValue(row, compiledPath, onError)`; accessor columns: the
   accessor). All-number columns (nullish → `NaN`) become a `Float64Array`. `formatted(column)` runs
   one `column:batch` (slot `format`): `column.format` or `defaultFormat` (+ `DK_UNRENDERABLE_VALUE`
   when the column has neither `cell` nor `format`). Hot-op ctx objects come from a ctx pool.
3. `pipeline/row.ts` — `Row<T>` class, methods on the prototype: `key`, `index`, `original`,
   `valid`, `issues`, `getValue(id)`, `getCellIssues(id)`.
4. `pipeline/runner.ts` — `createPipeline(host)`: base indices per data reference, per-step memo,
   `pipeline:run` (FALLBACK = last good row model) and `pipeline:step` (`where` =
   `features[i].rowModel`); a throwing `rowModel` → `DK_FEATURE_FAILED` (`hook: 'rowModel'`), the
   step passes its input through, `status: 'error'`. The same `RowModel` object is returned while
   nothing changed.
5. Extend `RowModelContext` (`run`, `columns`, `getColumnValues(id)`, `getFormattedValues(id)`).
6. Wire into `createTable`: `getRowModel` on the table literal (before `installApis`, so no feature
   can take the name); row model invalidated on data / state / columns change and recomputed before
   listeners are notified (or lazily by `getRowModel`); `run` increments per pipeline run.
7. Tests: memo hits (spy counts), stage order, failure fallback, column cache (lazy, `Float64Array`,
   WeakMap release by data reference, one `DK_CALLBACK_FAILED` / `DK_UNRENDERABLE_VALUE` per column),
   `ctx.where` property (no row key / cell value), 100k-row memory measurement ≤ 5 MB.

## Out of scope

- `rowKey` duplicate / missing detection and fallback keys `key#n` (T11): `Row.key` uses `rowKey`
  when given, else the row index; no diagnostics here.
- Schema validity: `row.valid` is `true`, `issues` empty, `getCellIssues` empty (T22 / T23);
  `getInvalidRows` (T22). `explain` / `explainRow` and the tracer (T25).
- `DK_FEATURE_BAD_OUTPUT` / `DK_FEATURE_MUTATED_INPUT` (T27): a non-`Uint32Array` output passes the
  input through without a diagnostic here. `DK_CALLBACK_BAD_RETURN` for `format` (T27).
- Server mode (skipping server-mode steps), `rowCount` (T21). Time-slicing / `status: 'pending'`
  (T29). Search projection (T16). The built-in features (wave 6).
