# T10 — Options catalog `defineOptions` + `optionValidator` (plan)

Spec §3.5 (declarative catalogs), §3.4 (`optionValidator` on `table:init` / `table:setOptions`),
§8.3 (`DK_UNKNOWN_OPTION`, `DK_INVALID_OPTION`, `DK_OPTION_NO_EFFECT`). Depends on T05, T08.

## Goal

One catalog describes every option (the table's and each feature's). A generic validator reads it
at creation and on `setOptions`: unknown keys warn with a did-you-mean, wrong runtime types or
ranges throw `DatakableConfigError`, and options that do nothing in the current configuration
(read-once options changed by `setOptions`, feature `noEffect` rules) warn with the reason.

## Steps (test-first)

1. `catalog/options.ts` — `OptionRule` (`type`, `oneOf`, `check` + `expected`, nested `shape`,
   `once`, `noEffect(value, options)`), `OptionsSchema`, `defineOptions(schema, values?)` (returns
   `{ schema, values }`; a feature passes its factory options as `values`), `isOptionsDefinition`.
2. `catalog/suggest.ts` — did-you-mean over candidate names, using `Scorer.levenshtein` from
   `ex-search` (already a dependency; no new code for edit distance), case-insensitive, distance
   ≤ max(1, ⌊len/3⌋), best first.
3. `catalog/codes.ts` — the three codes (`DK_INVALID_OPTION` is `config: true`).
4. `catalog/table-options.ts` — the table schema, typed exhaustively against `TableOptions` (a new
   table option without a catalog entry is a compile error). Carry-overs: `timeout` > 0 or
   `Infinity` (rejects 0, negatives, NaN); `diagnostics.redact` ∈ `'safe' | 'keys' | 'full'` or a
   function; `name`, `strict`, `initialState`, `timeout`, `diagnostics`, `features` are `once`.
5. `catalog/validator.ts` — `validateOptions` (creation: table schema, feature definition shape,
   feature option values) and `validateOptionChange` (setOptions: the partial, plus no-effect for
   changed `once` keys). Config errors are thrown; warnings go through `emit`.
6. Wire into `createTable` (localized): validate right after the diagnostics hub exists and before
   features are ordered; in `setOptions`, validate before the op and keep the previous value of
   every `once` option (generalises the existing `features` revert).
7. `Feature.options` typed as `OptionsDefinition` (was the `unknown` placeholder).

## Decisions

- The validator is a direct pre-step of `table:init` / `table:setOptions`, not an interceptor in
  the chain: the runtime reports a throwing interceptor as `DK_INTERCEPTOR_FAILED` and skips it, so
  a config error could not reach the caller; and features / redaction / timeout are consumed before
  `table:init` runs.
- `setOptions` with an invalid value throws and keeps the previous options (§3.4 fallback table).

## Out of scope

- `DK_MODE_ORDER`, `DK_FETCHER_WITHOUT_SERVER_MODE` (T21); `requires.core` / `DK_FEATURE_INCOMPATIBLE`
  (T28); `defineDeprecation` / `defineSlot` (their own units).
- Schemas of the built-in features (each feature unit writes its own with `defineOptions`).
- Validating `ColumnDef` entries (column units) and `initialState` / `state` keys
  (`DK_STATE_UNKNOWN_KEY`).
- `docs/errors.md` sections (T38).
