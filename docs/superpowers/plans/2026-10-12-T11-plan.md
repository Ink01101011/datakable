# T11 — rowKey resolution + DK_DUPLICATE_ROW_KEY / DK_MISSING_ROW_KEY (spec §5.2)

## Design

- New module `packages/core/src/ingest/row-key.ts`: `resolveRowKeys(data, rowKey, report)` scans
  **all** rows once per (data reference, rowKey reference) and returns a `RowKeys` resolver:
  - keys are stable whatever filter / sort / page is active (computed over the full data);
  - only the rows that need a fallback are stored (`Map<index, key>`), so a clean data set keeps
    no per-row memory (100k-row budget §9.3); the raw key of a visible row is re-read at build.
  - duplicates: the first row keeps its key, later rows get `key#1`, `key#2`, … (a fallback that is
    itself taken moves on to the next `n`);
  - missing / `null` / non-string-or-number / NaN keys get `#index`;
  - a throwing `rowKey` function keeps T09's `DK_CALLBACK_FAILED` (slot `rowKey`) + `#index`.
- `fix` is computed from the data, only on the error path (`ingest/unique-fields.ts`):
  candidates are the primitive leaf paths of row 0 (depth ≤ 4, arrays / Dates not walked; a field
  missing from row 0 cannot be present in all rows), each checked over every row for a
  string/number value and no repeats. If no single field is unique and `rowKey` is a path, a pair
  `${row.<rowKey>}-${row.<field>}` is verified with exactly the string the suggested function
  builds.
- Codes in `ingest/row-key-codes.ts` (catalog, `redact: { key: 'rowKey' }`).
- `pipeline/runner.ts`: `keyReader` replaced by the memoised resolver (small, localized edit).

## Tests first (`ingest/row-key.test.ts`)

- unique keys: no diagnostic, keys = values; no-rowKey → index.
- duplicates: `key#1`, `key#2`, one `DK_DUPLICATE_ROW_KEY` with rows / count / unique fields; keys
  stable under a filter that hides the first occurrence; fix names only truly unique fields (a
  field unique in the first rows but repeating later is not suggested); pair suggestion; no
  candidate → generic fix.
- missing / null / object keys: `#index`, one `DK_MISSING_ROW_KEY`.
- rowKey function duplicates; redaction (`'safe'` hashes the key).
- reported once per data reference (re-run without data change → no repeat).
