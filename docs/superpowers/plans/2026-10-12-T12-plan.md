# T12 — Ingest checks + zero-config column derivation (plan)

Spec §5.3 (data checks on `data:ingest`), §4.1 (zero-config columns), §8.3 (codes). Depends on T09.

## Goal

When data is applied, check the column definitions against the data and say exactly what is wrong:
a column path that no row has (with a did-you-mean), a path some rows lack, and — when `columns` is
omitted — rows whose key sets differ. Without `columns`, derive them from the data.

## Steps (test-first)

1. `ingest/derive-columns.ts` — `deriveColumns(data, sample = 50)`: union of own enumerable
   top-level keys over the first `sample` object rows, first-seen order; keys whose value is a
   function in any sampled row are skipped. `createDerivedColumns()` memoises per data reference and
   returns the previous array when the key list is unchanged (pipeline step memo keeps hitting).
2. `ingest/data-check-codes.ts` — `DK_COLUMN_PATH_NOT_FOUND` (warn), `DK_COLUMN_PATH_PARTIAL`
   (info), `DK_INCONSISTENT_ROW_SHAPE` (info), each with `where`, instance-specific `problem`,
   `impact` and computed `fix`.
3. `ingest/data-checks.ts` — `createDataChecks(emit)` → `check(data, columns)`, memoised on the
   (data, columns) references:
   - explicit `columns`: for each key column, walk its path over the sampled rows. A segment missing
     (not `in`) or a primitive part-way counts as absent; a `null` / `undefined` intermediate is
     allowed (nullable paths, §4.1). Absent in every sampled row → NOT_FOUND with `suggest()` over
     the data's paths (depth ≤ 4, arrays / Date / functions are leaves, candidate count capped);
     absent in some → PARTIAL (count + first sample indices). Accessor columns are skipped.
   - no `columns`: compare each sampled row's key set to the union → INCONSISTENT_ROW_SHAPE (one
     emit; keys with their missing counts + sample rows).
   - Every read is guarded (throwing getters / Proxy traps skip the row); never throws.
4. Wire into `createTable` (small, localized): `setData` and a `columns` change in `setOptions`
   call `checks.check(data, options.columns)`; the runner's `getColumns` falls back to the derived
   columns when `options.columns` is omitted.
5. Export `deriveColumns` from the package index (additive).

## Bounds

All checks read only the first `INGEST_SAMPLE` (50) rows: cost is O(50 × columns × depth) per new
data reference, independent of data size. Candidate paths are collected only when a path is not
found.

## Out of scope

- `DK_DATA_MUTATED`, `DK_PERF_HINT` (T27 / T29); rowKey checks (T11); schema ingest (T22).
- Search weights / headers for derived columns, and a public `getColumns()` (T16 / T24).
- `docs/errors.md` sections (T38).
