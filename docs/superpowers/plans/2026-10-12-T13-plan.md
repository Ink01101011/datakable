# T13 — `columnFilters()` feature (spec §6.1) — implementation plan

## Shape
- Files: `packages/core/src/features/column-filters/{types.ts,match.ts,codes.ts,feature.ts,index.ts}`
  + tests (`column-filters.test.ts`, `column-filters.test-d.ts`). Core `index.ts`: one added
  `export * from './features/column-filters'` line (no shared `features/index.ts`, so parallel
  wave-6 units do not conflict).
- State slice `columnFilters`: `{ [columnId]: ColumnFilter }`, a tagged value per column whose
  kinds come from `FilterFor<PathValue>` (column-def.ts) plus `custom`:
  `{ type: 'equals', value }`, `{ type: 'contains', value: string }`, `{ type: 'in', value: V[] }`,
  `{ type: 'range', value: { min?, max? } }`, `{ type: 'custom', value?, fn(value, filterValue, row) }`.
- API: `setColumnFilter(id, filter | undefined)`, `resetColumnFilters()`.
- `rowModel` (stage `filter`): AND over active filters; reads `ctx.getColumnValues(id)` (Float64Array
  fast path for numeric columns), nullish / NaN cells never match, array cells match on any element,
  wrong runtime type → non-match + one `DK_FILTER_TYPE_MISMATCH` (warn) per column per run.
  `contains`: lower-case + NFC, normalised cell strings cached per column-values array (WeakMap).
  Custom `fn` throwing → row non-matching + one `DK_CALLBACK_FAILED` per column per run.
- `FilterFor` gains arrays of primitives (element kinds), so `filter` on a `string[]` column types.

## Steps (TDD)
1. Type tests (state / API typing per column, arrays, loose rows, custom).
2. Operator matrix runtime tests (each kind × string / number / bigint / Date / boolean / arrays /
   nullish / mismatch / inactive values / AND / NFC Thai), diagnostics, memo, custom fn throw.
3. Implement, gate.
