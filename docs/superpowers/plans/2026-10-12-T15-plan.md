# T15 — Sort `auto` strategy + overrides + `DK_SORT_STRATEGY` + `DK_SORT_COMPARATOR_INVALID` (plan)

Spec §6.4 (sorting), §3.4 (`column:batch`), §8.3 (codes), §8.5 (dependency feature detection), §9.1
(bundle: exsorted subpaths only), §9.3 (`sort auto` overhead at n ≤ 1k). Depends on T14 (native
sort) and the R6 carry-over (`RowModelContext.batch`, `sortBy` as a cell slot).

## Goal

`sorting({ algorithm })` and column `sortAlgorithm` choose how the index copy is sorted. `'auto'`
(default) picks per sort from one O(n) scan over the input indices: single column, default
comparator, every non-missing key a safe integer (numbers, `Date.getTime()`) → exsorted tim (nearly
sorted) / counting (range ≤ 4n) / radix (n ≥ 10k) / tim; anything else → native. Results equal the
reference stable sort (missing last in both directions, ties in input order).

## Steps (test-first)

1. `features/sorting/strategy.test.ts`: fast-check — every algorithm (auto, tim, radix, counting,
   merge, native) equals a reference stable sort over random int / Date / float / string / mixed /
   missing columns, asc and desc, single and multi column; `auto` choice per row of the §6.4 table;
   overrides (table, column, custom fn incl. throw / bad return); `DK_SORT_STRATEGY` (only with
   `debug: true`); `DK_SORT_COMPARATOR_INVALID` (NaN, non-number, asymmetric, dev only) → default
   comparator; exsorted probe (`DK_DEP_INCOMPATIBLE`) → native.
2. `features/sorting/strategy.ts`: scan (`intKeys`), `chooseAuto`, `runAlgorithm` over exsorted
   `exsorted/tim`, `exsorted/merge`, `exsorted/radix`, `exsorted/counting` (never the root).
   Missing keys are split off and appended in input order; desc negates the keys (still stable).
3. `features/sorting/codes.ts`: `DK_SORT_STRATEGY` (info) and `DK_SORT_COMPARATOR_INVALID` (warn).
4. `features/sorting/sorting.ts`: options `algorithm`, `debug`; strategy dispatch; dev comparator
   check; `sortBy` through `ctx.batch(id, 'sortBy', rows, body)`.
5. R6 carry-over (additive): `RowModelContext.batch` in `feature/types.ts`, implemented in
   `pipeline/runner.ts` by the column cache's `batch` (now exposed); `'sortBy'` cell slot in
   `intercept/cell-batch.ts` + `column:batch` op input; columnFilters' custom `fn` loop runs inside
   `ctx.batch(id, 'filterFn', …)` so `column:batch` interceptors see it.
6. `features/sorting/sorting.bench.ts`: auto vs direct native at n = 100 / 1k; 100k numbers on dist.
