# T16 — Feature `search` (client) — implementation plan

Spec §6.3 (client matching, ordering, state shape, API names). Depends on T08 (`defineFeature`) and
T09 (pipeline runner, column cache).

## Files (all new, under `packages/core/src/features/search/`)

- `search-index.ts` — the projection `{ i, c0, c1, … }` built from the column cache's **formatted**
  values, plus the matcher (an `ExSearch` instance, or a contains fallback). Memoised per
  (data reference, columns reference) in a `WeakMap`; built lazily on the first non-blank query.
- `search.ts` — `search(options)` factory via `defineFeature` (stage `'search'`), options schema via
  `defineOptions`, state `{ input, query, status, error? }`, API `setSearch` / `flushSearch` /
  `cancelSearch` / `clearSearch`.
- `index.ts` — module exports. `packages/core/src/index.ts` gets one added `export *` line.
- Tests: `search.test.ts` (behaviour through `createTable`), `fallback.test.ts` (ex-search capability
  missing → `DK_DEP_INCOMPATIBLE` + contains fallback, `vi.mock`), `search.test-d.ts` (StateOf / ApiOf).

## Behaviour

1. Searchable columns: columns with a numeric `search` weight > 0. When no column declares a weight,
   every column is searchable at weight 1 (spec's zero-config rule).
2. Blank / whitespace-only query → input indices returned unchanged (ex-search returns `[]`).
   The query is trimmed before matching.
3. Results map back by the projection's `i` field (row index), never by object identity.
4. Output order: score descending, ties by original row index (re-sorted by DataKable, exact float
   scores; ex-search's radix ranking quantises). A later sort stage overrides this naturally.
5. Filtered input: the matcher searches only the input rows (subset of projection references,
   memoised on the input array reference). Full input uses the projection directly.
6. Per-step memo inside the feature on (input reference, trimmed query, index) so a slice change that
   does not change `query` (T17 typing: `input` / `status`) does not re-run matching.
7. No searchable column (e.g. `columns` omitted until T12/T24 derive them) with a non-blank query:
   rows pass through, `DK_OPTION_NO_EFFECT` once per columns reference.
8. API (immediate strategy): `setSearch(q)` sets `input` and `query`, resolves
   `{ status: 'applied' }`; `flushSearch()` commits `input` → `query`; `cancelSearch()` is a no-op
   in immediate mode (status back to `'idle'`); `clearSearch()` empties both. Promises never reject.

## Out of scope

- Typing strategies (debounce / throttle, `wait`, `behavior`, `minLength`, `commitOn`), status
  `'pending'` — T17.
- Async `searchFn`, `status: 'searching'` / `'error'`, `superseded`, `DK_SEARCH_FAILED`,
  `useWorker` — T19.
- `mode: 'server'` and mapping search status into `RowModel.status` — T21.
- Zero-config column derivation — T12 / T24. Default preset — T24.
- Time-slicing the projection build (`scheduler.yield`) — T29.
