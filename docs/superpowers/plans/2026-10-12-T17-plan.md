# T17 — Search typing (§6.3) — implementation plan

## Scope
1. `search({ typing })` option (validated by `defineOptions`, nested `shape`):
   `strategy` (`'immediate' | 'debounce' | 'throttle'`, default `'immediate'`), `wait` (ms or
   kk-debounce temporal object, default 300), `behavior` (`'trailing' | 'leading'`, debounce only),
   `minLength` (default 0; shorter trimmed input = empty query), `commitOn` (`'type' | 'enter'`).
   `DK_OPTION_NO_EFFECT` for `wait` / `behavior` where the strategy or `commitOn` ignores them.
2. `createApi` `commit()` seam: `setSearch` updates `input` at once; `query` follows through
   `debouncedSignal` (`kk-debounce/debounceSignal`) or `throttle` (`kk-debounce/throttle`).
   `status: 'pending'` while a commit is scheduled. `flushSearch` = Enter (cancel + apply now),
   `cancelSearch` drops the scheduled commit, `clearSearch` cancels and empties both.
   Timers are cancelled on `table:destroy` (feature interceptor, per-table host in a WeakMap).
3. `RowModel.status` gets the search status via `PipelineHost.status()` in `create-table.ts`
   (precedence error > fetching > searching > validating > pending > idle); every change notifies.
4. R6: pagination auto-reset compares only `query` for search-stage slices with a `query` field.
5. Tests with fake timers per strategy; type test for `typing`.

## Out of scope
- `mode: 'server'` defaults (server: debounce 300 ms, minLength 2) — the `mode` option is T21's.
- Async `searchFn`, promise outcomes `superseded` / `error`, `'searching'` producer — T19.
- `useWorker` — T19.
