## Behaviour

- One `AbortController` per request; the caller's `ctx.signal` (if any) is linked into it, and
  `ctx.signal` is replaced by the controlled signal before `next()`, so inner interceptors and the core
  pass it to the user callback.
- Latest-wins per `input.source` (`fetcher` and `searchFn` do not supersede each other). A new
  request settles the previous one as `superseded`: its signal is aborted and its `run` promise
  resolves at once with the caller's `FALLBACK` (previous results). A late result of a callback that
  ignores the signal is dropped; a late rejection is swallowed (no unhandled rejection).
- `timeout` (default 30 000 ms; `Infinity` disables): aborts, emits `DK_ASYNC_TIMEOUT`, resolves with
  `FALLBACK`.
- Outcome in `ctx.meta.get(ASYNC_STATUS)`: `applied` | `superseded` | `timeout` | `aborted` | `error`.
  Callers apply the result only on `applied`. An `AbortError` rejection is `aborted`, not an error;
  any other rejection is `error` and is rethrown to the errorBoundary.
- `table:destroy` aborts every in-flight request (`aborted`).
- `DK_ASYNC_TIMEOUT.where` is built from `source` (a closed set of option names), never from
  `ctx.where`; asyncControl never writes `ctx.where`.

## Tests first

- applied path; signal passed to the core; superseded result never applied when the callback ignores
  the signal (late resolve and late reject); sources independent; timeout (fake timers) emits
  `DK_ASYNC_TIMEOUT` once and keeps previous results; caller signal abort → `aborted`; AbortError
  rejection → `aborted`; other rejection → boundary fallback + `error`; sync throw from core;
  `table:destroy` aborts in-flight; no unhandled rejections; catalog entry complete.
- Property (fast-check): arbitrary params / error messages / ctx.where-free sources — no sentinel
  reaches `where`, fingerprint, docs or details of any emitted diagnostic; ctx.where is unchanged.
