# T19 plan — async `searchFn`, search promise API, `DK_SEARCH_FAILED`, fetch retry

Spec §6.3 (search), §6.6 (status), §7.1 (fetcher), §8.3, §8.6. Depends on T17 (typing), T18/R3
(asyncControl, `getTableInternals(table).request`), T21 ('searching' status from `request`).

## Search (`packages/core/src/features/search/`)

1. `search({ searchFn })` option (`type: 'function'`). `searchFn({ query, rows, columns, signal })`
   resolves `readonly T[]` (references from `rows`, relevance order) or `{ keys: RowKey[] }`.
   - `mode: 'server'` + `searchFn` → `DK_OPTION_NO_EFFECT`; `threshold` / `fuzzyMaxDistance` /
     `caseSensitive` with `searchFn` → `DK_OPTION_NO_EFFECT` (searchFn replaces matching).
2. Applying a non-blank query with `searchFn` runs it through
   `getTableInternals(table).request('searchFn', …)` (asyncControl: latest wins, abort, timeout).
   - slice `status: 'searching'`, `query` stays the previous applied value (the row model keeps the
     previous results) until the result is applied; then `query` = the new query, `'idle'`.
   - failure (throw / reject / bad result / timeout): `status: 'error'`, `error`, previous results
     kept; `DK_SEARCH_FAILED` (not for timeout: `DK_ASYNC_TIMEOUT` already reports it).
   - `AbortError` from the callback is not an error (status back to idle, outcome superseded).
   - data change (or an externally set `query` with no result) re-runs `searchFn` once per
     (query, data) after the pipeline run (microtask); meanwhile the previous result is mapped
     onto the new data by row identity / row key.
3. Promise API: `setSearch` / `flushSearch` resolve when their query is actually applied
   (`applied`), when a later query replaces it or it is cancelled / the table destroyed
   (`superseded`), or `error`. Never reject.
4. Row model step with `searchFn`: input ∩ result, in result order (relevance).

## Fetch retry (`table/create-table.ts`, small, localized)

5. `table.refetch(): Promise<{ status: 'applied' | 'superseded' | 'error' }>` — reruns the fetcher
   with the current params; never rejects. Core method on the table literal (before installApis).
6. `setOptions({ fetcher: newFn })` refetches (new reference) even with unchanged state.
7. `DK_FETCH_FAILED` fix text names `table.refetch()`.
