## Behaviour

- State `{ pageIndex: 0, pageSize: 10 }`; `pagination({ pageSize })` sets the starting size.
- Options (`defineOptions`): `pageSize` (positive integer), `autoResetPageIndex` (boolean, default
  `true`).
- `rowModel` (stage `paginate`): `indices.subarray(start, start + size)` of the *effective* page
  (`pageIndex` clamped to the last page), so the visible rows are never an empty page past the end.
  Returns its input unchanged when the whole input fits on page 0.
- API: `setPageIndex(i)` (clamped to `[0, pageCount - 1]`), `setPageSize(n)` (anchor: new index =
  `floor(firstRow / n)`), `nextPage`, `prevPage` (no-ops at the bounds), `getPageCount`
  (`ceil(rowCount / pageSize)`, 0 for no rows), `canNextPage`, `canPrevPage`.
- Row count: `table.getRowModel().filteredCount` (client mode). Seam for T21: one `rowCount()`
  function where server mode will read `rowCount`.
- Auto-reset: an interceptor on `state:dispatch` and `table:setOptions` compares the state before
  and after the core; when a `filter` / `search` / `sort` stage slice changed and the pagination
  slice did not, it sets `pageIndex: 0` inside the same operation (one notification, no page flash).
  A dispatch that changes the pagination slice itself is respected.
- Validation (never silent): an invalid `pageIndex` / `pageSize` passed to the API is ignored with
  `DK_INVALID_PAGINATION`; an invalid slice written through `setState` / `setOptions({ state })` /
  `initialState` is replaced by a valid one with the same code, so the row model never sees it.
- Clamp: a table listener (subscribed at `createApi`) sets the clamped `pageIndex` when the row
  count shrinks below the current page (covers data changes, async ingest, filters with auto-reset
  off).
