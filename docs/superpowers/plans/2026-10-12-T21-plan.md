# T21 plan — data modes, server source `fetcher`, `rowCount`

Spec §7.1, §6.5, §6.6. Branch `feat/core-T21` from develop 9abeb35.

## Steps (test-first)
1. **Feature `mode`.** `Feature.mode?: 'client' | 'server'` (feature contract, additive); the
   option validator checks it (`FEATURE_SHAPE`). Built-ins (`columnFilters`, `search`, `sorting`,
   `pagination`) take `mode` as a factory option (`defineOptions` rule) and set it on the feature.
   The runner skips the `rowModel` of server-mode features.
2. **Config checks** (`source/modes.ts`, codes in `source/fetch-codes.ts`), at creation and on
   `setOptions`: `DK_MODE_ORDER` (server steps must be a prefix; names both features, two fixes)
   and `DK_FETCHER_WITHOUT_SERVER_MODE`.
3. **Fetcher.** `options.fetcher(params)` → `{ rows, rowCount }`. Params carry only the state of
   server-mode built-ins (`query`, `filters`, `sort`, `pageIndex`, `pageSize`) plus `signal`. Runs
   at creation and whenever those params change (checked once per flush, so a sort change plus
   the pagination auto-reset is one request). Goes through `getTableInternals(table).request`
   (`async:request`, asyncControl). Result shape is validated (`DK_FETCH_BAD_RESPONSE`); rejections
   are `DK_FETCH_FAILED`; superseded requests `DK_FETCH_ABORTED` (info). Applied rows go through
   `data:ingest` (schema + data checks) and mark the table loaded.
4. **Status.** `request()` counts in-flight requests per source: `'fetching'` (fetcher),
   `'searching'` (searchFn). Every change marks the row model dirty and flushes; a settle is one
   batch (status + applied rows → one notification). Failure → `'error'` (+ `isInitialLoad` stays
   `true` on a failed first request). Precedence error > fetching > searching > validating > idle.
5. **`rowCount`.** Table option `rowCount`; `TableInternals.rowCount()`; pagination in server mode
   counts pages from it (fetcher result, else the option, else `DK_ROW_COUNT_MISSING` and
   `data.length`).

## Out of scope
- The `searchFn` option / API and `DK_SEARCH_FAILED` (T19): only the `'searching'` status seam in
  `request()` is here.
- Search typing / `'pending'` (T17), `initialData` / no re-fetch on hydrate (T32), sort strategy
  (T15), validity (T23).
- Forwarding third-party server-mode feature state to the fetcher (only the spec's keys).
