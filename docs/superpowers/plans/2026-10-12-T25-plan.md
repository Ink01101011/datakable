# T25 — `tracer` interceptor + `explain()` + `explainRow(key)` — plan

Spec §8.4 (with §3.4 tracer row, §8.2 redaction / prod stripping, §9.1 "trace of the last run only").

## Design

- **Runner seam (additive, `pipeline/runner.ts`)**: `Pipeline.steps()` returns the last run's step
  records `{ feature, input, output, cached, failed }` — references to the index arrays the memo
  already holds (no copies, no per-row bookkeeping). `Pipeline.keyOf()` returns the resolved row-key
  reader of the last build.
- **`diagnostics/tracer.ts`**: `tracer()` interceptor on `pipeline:run`, `pipeline:step`,
  `state:dispatch`. Records timings and per-step counts of the last run only, per table, in a
  `WeakMap` (`diagnostics/trace-store.ts`). `createTable` installs it in development only
  (`DEV ? [tracer()] : []`, folded away in production builds). In production it is opt-in with
  `interceptors: [tracer()]`.
- **`diagnostics/explain.ts`**: `explainTable(host)` / `explainRow(host, key)` build structured
  results from the runner records (+ tracer timings when present). They never change state: the
  only work is the lazy row-model computation `getRowModel()` would do anyway.
  - `explainRow` walks every stage in pipeline order using the recorded step input/output: schema
    (valid / flagged / dropped), each client step (kept + position / removed), server-mode steps
    (skipped). The first step whose output lacks the row is `removedBy`. For a removal by the
    built-in `columnFilters`, each active filter is replayed on the single row (pure step, no
    emit, no interceptors) to name the filters that reject it. Search and sort are never replayed
    (they keep internal caches); pagination reports the row's page.
  - Everything printed goes through the table's redaction policy: keys through `redactLocation`,
    cell / filter values through `redactDetails` (`'value'`), sensitive columns never shown,
    schema issues through `scrubSchemaIssue`, search query by length only.
- **`diagnostics/explain-text.ts`**: the console text (`toString()`), development only; production
  `toString()` is `JSON.stringify` of the structured result.
- **`create-table.ts`** (small): `explain` / `explainRow` on the table literal before
  `installApis`; one host object; tracer added in `withControl`.
- `Table` type gets `explain()` / `explainRow(key)`.

## Tests first

`diagnostics/explain.test.ts`, `diagnostics/tracer.test.ts`: explain counts per step, schema
dropped / flagged, tracer timings in dev, recomputation without the tracer, explainRow pinpoints
the removing step for columnFilters (with the filter), validity, search (query length, threshold,
searchFn), pagination (page), a custom feature, server-mode skip, schema dropped / flagged, unknown
key, no state change / no notification, redaction (`'safe'` hash + sentinel absent, sensitive
column, `'keys'` raw key), API-name conflict (a feature cannot take `explain`).

## Out of scope

- `DK_PERF_HINT` / time-slicing from tracer timings (T29).
- A `trace: true` table option (tracer is opt-in via `interceptors: [tracer()]` in prod instead).
- Per-row search scores (ex-search scores are internal to the search step; not replayed).
- Packaging the explain/tracer modules as separate entries (T36).
