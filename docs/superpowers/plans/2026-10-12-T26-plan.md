# T26 — Redaction plan (spec §8.2)

## Goal

`'safe'` / `'keys'` / `'full'` redaction of every diagnostic before any consumer sees it:
user `diagnostic:emit` interceptors, the `redact` seam, dedupe, the ring buffer, `onDiagnostic`,
the console sink and `DatakableError` messages.

## Design

- `diagnostics/redact.ts` (new):
  - `hashRowKey(key)` — 32-bit FNV-1a over `String(key)`, rendered `h:xxxxxxxx`.
  - `describeValue(v)` — value *type* summary (`string(12)`, `number`, `array(3)`, …).
  - `scrubSchemaIssue(issue, r)` — `{ path, message }`; under `'safe'` / `'keys'` the message is
    DataKable's own text (`invalid value at a.b`), the validator message only under `'full'`.
  - `scrubError(e)` — `error.name` + `code` only (fetcher errors). Full error stays in `context.cause`.
  - `resolveRedaction(option, dev)` → `Redactor` (level, custom fn, sensitive columns, rowKey sensitivity).
  - `redactLocation` / `redactDetails` — apply the policy.
- Definitions declare which detail fields carry user data:
  `defineDiagnostic({ ..., redact: { key: 'rowKey', value: 'value', issues: 'schemaIssues' } })`.
  Kinds: `rowKey`, `rowKeys`, `value`, `values`, `schemaIssues`, `error`.
- `buildDiagnostic` redacts first: `where` from raw details → `redactLocation`; details →
  `redactDetails`; problem / impact / fix text, `formatWhere`, fingerprint and the prod docs
  `?where=` are all built from the redacted values. So nothing downstream can see raw keys.
- Order in the hub: enrich + redact (build) → user `diagnostic:emit` interceptors → `redact` seam
  (T05) → dedupe → buffer → sinks → strict.
- `DiagnosticsOptions.redaction`: `RedactLevel | { level?, redact?(path, value), sensitiveColumns?(),
  rowKeySensitive?() }`. Default level: `'keys'` in dev, `'safe'` in prod. `'full'` in prod emits
  `DK_UNSAFE_REDACTION` (warn) once at hub creation.
- Sensitive columns are never logged (`[sensitive]`) at any level, and win over the custom fn.
  A sensitive rowKey column → keys hashed at every level.

## Tests (first)

- `redact.test.ts`: hash stability/format, type summaries, levels × field kinds, sensitive,
  custom fn (+ throwing custom fn), schema/fetcher scrubbing.
- `sentinel.test.ts`: a sentinel string as row key, value, schema message, error message and
  sensitive value; under `'safe'` assert it is absent from: `onDiagnostic` payload (minus cause),
  `toJSON`, fingerprint, docs URL, dev and prod console output, user interceptor input,
  getDiagnostics, strict `DatakableError` message.

## Out of scope

- Calling `scrubSchemaIssue` / `scrubError` from schema ingest (T20) and the fetcher (T28): those
  modules do not exist yet; they annotate their codes' fields (`schemaIssues`, `error`) or call the
  exported functions.
- Wiring `createTable({ diagnostics: { redact } })` and column `sensitive` / `rowKey` into the hub
  (T07 / options units).
- Validating an invalid `redact` level with `DK_INVALID_OPTION` (optionValidator unit); an unknown
  level falls back to `'safe'`.
