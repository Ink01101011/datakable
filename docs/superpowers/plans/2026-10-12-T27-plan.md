# T27 plan — dev checks

Spec §5.3, §3.4 (`slotContract`, `devChecks`), §3.5 (`defineSlot`), §8.2 (prod stripping), §8.3.
Done when: each check fires in dev and is absent from the prod build.

## Steps (test-first)

1. **`DEV` must fold in a prod bundle.** `diagnostics/env.ts` reads `typeof process === 'undefined' ||
   …`, which a bundler cannot fold (`D=typeof process>"u"||!1` in a rolldown prod bundle), so no
   `if (DEV)` branch is stripped and `DEV` is `true` in browsers. Change it to the bare
   `process.env.NODE_ENV !== 'production'` read (the form §8.2 names).
2. **`defineSlot` + `DK_CALLBACK_BAD_RETURN`** (`catalog/slots.ts`): slot registry
   (`name`, `returns`, `fallback`), the built-in `format` slot, and the warning. The column cache
   counts non-string `format` returns in the existing `column:batch` (only on the non-string path,
   only in dev) and reports one warning per column batch. Values are still coerced via the default
   formatter.
3. **`DK_FEATURE_BAD_OUTPUT` / `DK_FEATURE_MUTATED_INPUT`** (`pipeline/dev-checks.ts`): around each
   recomputed `rowModel` call (dev): a sampled hash of the input before / after (bounded: 64
   positions), and an output check (a `Uint32Array` whose indices are `< data.length`). A bad output
   passes the input through, marks the run `status: 'error'` and is not memoised.
4. **`DK_DATA_MUTATED`** (`table/data-mutation.ts`): a fingerprint (length + 16 sampled rows:
   identity + shallow hash of the first 64 own keys) taken when `options.data` is ingested;
   `setOptions` with the same `data` reference compares it and warns.
5. All four definitions are registered only under `DEV` (`DEV ? [defineDiagnostic(…)] : []`), so the
   codes, text and check code are all absent from a prod bundle. Prove with a rolldown prod build
   + grep; dev build must contain them.

## Out of scope

- A chain-interceptor form of `slotContract` / `devChecks`: a `column:batch` interceptor cannot see
  per-cell returns without per-cell dispatch, and the step core already coerces the output. The
  checks run inline, driven by the catalogs (same reasoning as `optionValidator`, R5).
- `DK_SORT_COMPARATOR_INVALID` (comparator sanity, T14) and `cell` slot checks (React, T33/T34).
- Repairing upstream memos after a feature mutated its input (warn only, spec fallback "—").
- `docs/errors.md` anchors (T38).
