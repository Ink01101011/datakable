## Behaviour

- Registry `{ v: 1, cores: [{ version, id }], packages: { name: version }, reported: Set }`, created
  on first use; fields read defensively so a registry left by another core version never throws.
- Each core copy registers itself on its first `createTable` (not at module load: no top-level side
  effect, `sideEffects: false`). The copy that finds another copy already registered emits
  `DK_DUPLICATE_CORE` (error, not config: the table still works) once.
- Every `createTable` compares the registered fixed-group packages (`registerPackage`) with this
  core's `VERSION`; each differing package is reported once per core copy (`DK_VERSION_MISMATCH`).
- `requires.core` of each installed feature is checked against `VERSION`; unmet or unparseable →
  `DatakableConfigError` `DK_FEATURE_INCOMPATIBLE` at creation, before APIs are installed.
- `warnDeprecated(def, emit?)` emits `DK_DEPRECATED` with `since`, `removeIn`, `replacement`,
  optional `codemod`, once per `api` per session (registry `reported`, so shared across copies).
- `detectCapability` runs the probe (a throw counts as missing), emits once, returns the result so the
  caller picks the native path or its fallback.
- `where` of every code here is built from package names, feature names and option paths — never row
  data. `ctx.where` of `diagnostic:emit` no longer carries row keys.

## Tests first

- semver: caret/tilde incl. `^0.x`, x-ranges, comparators, AND/OR, prerelease ignored, invalid.
- two-core test: two module instances of core (`vi.resetModules`) in one process; the second's first
  table gets `DK_DUPLICATE_CORE`; same copy creating more tables does not.
- version mismatch reported once per package; equal versions silent.
- feature `requires`: met → installs; unmet → throws config error with feature `where`, no API
  installed; invalid range → same code with the "use a semver range" fix.
- deprecation once per API per session; global hub when no `emit`; fields carried.
- capability: ok → silent + `true`; missing / throwing probe → one `DK_DEP_INCOMPATIBLE` + `false`.
- catalog: every code has where + non-empty fix.
- ctx.where property (fast-check): row keys / cell values never appear in any `ctx.where` seen by a
  `'*'` interceptor or in an interceptor-failure slot.
