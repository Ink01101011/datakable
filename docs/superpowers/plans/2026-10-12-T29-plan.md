# T29 plan — env fallbacks, time-slicing, DK_PERF_HINT (spec §9.1, §6.6, §8.3)

Done when: no single task > 50 ms building a 100k search projection (measured on dist).

## Baseline (dist, NODE_ENV=production, Node 25.2.1, Apple M4 Pro, 100k rows, 2 searchable columns)

| case | total | longest task |
|---|---|---|
| search: first query (projection + match) | 69 ms | 70 ms |
| search: later query | 64 ms | 64 ms |
| string sort (Intl.Collator) | 112 ms | 112 ms |
| numeric sort | 3.7 ms | 3.7 ms |

## Design

1. `pipeline/slice.ts` (new): a per-table slicer. `ctx.slice(key, job)` on `RowModelContext` runs a
   generator job synchronously for one slice (≤ ~8 ms, time checked at each `yield`). Finished →
   its result now (small tables never go async). Not finished → `undefined`: the step returns a
   stand-in (its previous output for the same input, else the input), the run is not memoised and
   the row model is `'pending'` (precedence error > fetching > searching > validating > pending >
   idle). The rest runs after `scheduler.yield()` (fallback `setTimeout`, `DK_ENV_FALLBACK` once per
   table); when the job ends the table recomputes and notifies (status back to `'idle'`).
   - No slicing during SSR (`phase: 'ssr'`) and for a table's first row model (hydration parity:
     the first client row model equals the server one).
   - A job's error is rethrown into the step that asks for it (normal `DK_FEATURE_FAILED` path).
   - Jobs no step asked for in a run are cancelled; `destroy()` cancels all.
2. Search: the projection (formatted values per column, one slice each; items in 4k-row chunks,
   values lower-cased once when `caseSensitive: false`) and the matching (4k-item chunks; ex-search
   scores items independently, so chunking is exact) are sliced jobs. `searchFnStep` memoised on
   (input, hits) — no `Uint8Array(data.length)` per run.
3. Sorting: under `algorithm: 'auto'` and n ≥ 10k, a string column (strings + missing only) gets
   precomputed collation ranks (sliced merge sort of the distinct strings with the collator; equal
   strings share a rank), cached per values array; the sort then runs on integer keys (counting /
   radix) — later sorts of that column take a few ms. `DK_ENV_FALLBACK` when `Intl.Collator` does
   not support the requested `locale`.
4. `DK_PERF_HINT` (info) from the tracer: a traced `pipeline:step` slower than 50 ms (§9.3 budget)
   reports feature, stage, ms, rows and a server-mode / worker suggestion.
5. New codes follow the T36 pattern (`defineDiagnostic(meta, DEV && envMessages.X)`, keep-alive via
   `useDiagnostics`, `messages` entry, `fault-injection/catalog.test.ts` entry).
6. R9 carry-over: the HOT_COST text is inlined in the DEV branch of `intercept/runtime.ts` and in
   the message builder; no exported constant ships in production.

## Out of scope

- Workers (`useWorker`), server-mode changes, `AbortSignal.any` (core does not use it).
- Slicing user callbacks (`format`, `sortFn`, filter fns): one column batch stays one task (§3.4);
  `DK_PERF_HINT` reports a slow step instead.
- Slicing the native comparator sort itself (`sortFn`, mixed-type columns, forced algorithms).
- CI budgets (T37), docs/errors.md (T38).
