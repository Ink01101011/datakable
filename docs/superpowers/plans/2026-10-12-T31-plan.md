# T31 — React `useDataTable` (plan)

Spec §10 (+ §3.2, §6.6, §8.3 `DK_UNSTABLE_COLUMNS`, §8.5 `registerPackage`). Worktree
`datakable-wt/T31`, branch `feat/core-T31`.

## Steps (test-first)

1. `packages/react/src/use-data-table.test.tsx` / `.test-d.ts`: renderHook tests for every point
   below, then implement.
2. `useDataTable(options)` in `packages/react/src/use-data-table.ts`:
   - the table is created once per component instance (lazy `useRef`, reused across the StrictMode
     double render in React 19), with `registerPackage('@datakable/react', VERSION)` before the
     first `createTable`;
   - `useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot)`; the snapshot is a view
     (`Object.create(table)` + `state` + `rowModel`), cached on (state, row model, notification
     count) so every notification (status / `isInitialLoad` included, §6.6) re-renders once;
   - options are synced in a layout effect with `table.setOptions(changedKeys)`, never during
     render; read-once options (`features`, `schema`, `initialState`, …) are not forwarded;
   - `fetcher`, `onStateChange`, `onDiagnostic` are stable wrappers calling the latest prop
     (latest-ref): a new inline function never refetches; presence changes are forwarded;
   - controlled slices: `state` is forwarded when a slice changed (`Object.is` per slice);
   - render-loop guard: in the re-render caused by the hook's own sync, a new `columns` with the
     same shape, a shallow-equal `data`, or a new `rowKey` function are not forwarded again (they
     come from the same inputs), which ends the loop an inline `columns` / `data` would cause;
   - dev: `DK_UNSTABLE_COLUMNS` (new same-shape columns on consecutive renders) and
     `DK_UNSTABLE_OPTION` (`data` / `fetcher` / `rowKey` / feature function options);
   - `onDiagnostic` calls made while rendering (creation, lazy pipeline run) are delivered in the
     next layout effect, so a user `setState` there is never a setState-in-render;
   - destroy on unmount, deferred one microtask so the StrictMode effect re-run keeps the table;
     a table destroyed while hidden (`<Activity>`) is re-created on the next mount.
3. `datakable`: `useDataTable` with the default preset (fresh `createDefaultFeatures()` per
   component instance), shadowing the re-exported one (additive export).
4. Core, additive: `emitTableDiagnostic(table, code, details)` (bindings report catalog codes on a
   table's hub), via a new `emit` field on the internal table seam.
