## Behaviour

1. Columns: `getOptions().columns ?? deriveColumns(getData())`.
2. Header: sort button when `toggleSort` exists and `sortable !== false`; Shift+click = multi;
   `aria-sort` ascending / descending / none.
3. Search (when `state.search` exists): `input` bound to `state.search.input`, `setSearch` on change,
   Enter = `flushSearch`, Esc = `clearSearch`; spinner (`role=status`) while `pending` / `searching`;
   `data-status` = search status.
4. States (§6.6 + §10, USER DECISION): Loading = `isInitialLoad` && fetching/searching/validating;
   Error = `status === 'error'` && `isInitialLoad`; otherwise rows, with a refresh indicator
   (`data-status`) for any non-idle status; Empty when no rows to show. Root carries `data-status`
   and `data-initial-load`.
5. Flagged rows: `data-invalid` / `aria-invalid` on the row and on cells with issues, redacted
   `title` (issue paths only, never the schema message), `⚠` marker; `invalidCell` gets
   `issues: row.getCellIssues(id)`.
6. Cell slots: `cell` / `invalidCell` / `format` throws → `⚠` + `DK_CALLBACK_FAILED` (emitted after
   commit, per column); a thenable from `cell` → `⚠` + `DK_CALLBACK_BAD_RETURN` (dev).
7. Body error boundary: a component inside `cell` throws → `DK_RENDER_FAILED`, Error state in the
   body, header / search / pagination survive; reset on the next row model.
8. `components={{ SearchInput, Pagination, Empty, Loading, Error }}` overrides.
