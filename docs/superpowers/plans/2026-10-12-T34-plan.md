# T34 plan — React per-cell error boundaries + `render:*` operations (`DK_RENDER_FAILED`)

Spec §3.4 (operation registry), §8.3, §8.6, §10. Builds on T33 (body boundary, per-cell `⚠` for
throwing / contract-breaking callbacks, `data-status` / `data-initial-load`, `invalidCell` issues).

## Steps

1. Baseline: `packages/react/src/data-table.bench.tsx` — mount + unmount of 100 rows × 10 columns
   (1,000 cells), plain values vs `cell` returning an element. Record numbers before any change.
2. Tests first (`data-table.fault.test.tsx`, `render-codes.test.ts`):
   - a component returned by `cell` throws in one row → that cell renders `⚠`, every other cell and
     row renders, the table API keeps working (sort), `DK_RENDER_FAILED` at
     `operation render:cell at columns[1].cell` with `column` / `row` / `errorName`, `cause` passed
     to `onDiagnostic`, no row data; the cell renders again when its row / the columns change;
   - same for a component returned by `invalidCell` (`columns[i].invalidCell`);
   - the body boundary keeps its job for components outside cells (a throwing `components.Empty`):
     `operation render:table`, Error state with Retry, header survives;
   - `render:table` / `render:cell` are registered (`getOperation`), sync, not hot.
3. `render-codes.ts`: `DK_RENDER_FAILED` details gain `op: 'render:cell'`, `slot`, `column`, `row`;
   `where` = `{ kind: 'operation', op, slot? }`; problem / impact / fix per op. Declaration-merge
   `Operations` with `render:table` / `render:cell` and `registerRenderOperations()`.
4. `data-table.tsx`: `CellBoundary` (class, `getDerivedStateFromError`, emits in
   `componentDidCatch`, fallback `⚠`, reset when the row's `original` or the column def changes).
   Wrapped only around object content returned by `cell` / `invalidCell` — primitives (strings,
   numbers, `format`, the default formatter) cannot contain a component, so the happy path for them
   is unchanged.
5. Re-run the bench; update the READMEs' error sentences.

## Out of scope

- Running interceptor chains for `render:*` (spec §3.4: boundaries, not per-cell chains).
- Server-mode total in the pagination UI: the server `rowCount` is not on the public table API
  (`TableInternals.rowCount()` is internal); exposing it needs a core API addition (pagination
  `getRowCount()`), left for a core unit. `getPageCount()` already uses the server total.
- Error boundaries during SSR (React's server renderer does not run them).
- `styles.css` (T35), `docs/errors.md` (T38).

## Results

`pnpm vitest bench --run --reporter=verbose packages/react/src/data-table.bench.tsx` (mount +
unmount, 100 rows × 10 columns; Apple M4 Pro, Node 25.2.1, happy-dom; A/B by stashing the change,
two rounds each; other worktrees were running, so `min` is the stable figure):

| 1,000 cells | before min / mean (ms) | after min / mean (ms) |
|---|---|---|
| plain values (`format`) | 8.66–8.78 / 11.6–13.1 | 8.50–8.82 / 12.1–13.1 (no boundary: unchanged) |
| `cell` returns an element | 14.45–14.60 / 18.4–21.1 | 15.47–15.98 / 20.2–23.5 |

An element cell pays ~1–1.4 µs for its boundary (one class fiber + `getDerivedStateFromProps`), the
cost React requires for a per-cell boundary; primitive cells pay nothing.

Size (standard method, T37 brief: esbuild 0.27.7 min ESM, production, gzip -9, from
`datakable` dist): `DataTable` 39,558 → 39,830 B (+272); `useDataTable` 37,017 → 37,034 B (+17;
the ops are registered on the first `<DataTable />` render, not at import, so hook-only bundles
do not carry it).
