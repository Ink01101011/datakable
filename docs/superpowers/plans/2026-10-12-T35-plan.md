# T35 plan — optional `datakable/styles.css`

Spec §10 ("unstyled, with `data-*` hooks only. An optional `datakable/styles.css` is available"),
§1 (`@datakable/react` ships the optional styles.css), §12 (`sideEffects: false` with an explicit
exception for `messages` / `styles.css`). Depends on T33 (develop ca610e9).

## Stylesheet (`packages/react/src/styles.css`, new)

- Styles `<DataTable />` only through the hooks it already renders: `[data-datakable]`,
  `data-status`, `data-initial-load`, `aria-busy`, `[data-dk-state=loading|empty|error]`,
  `[data-dk-refresh]`, `th[aria-sort]` / `data-sort` / `[data-dk-sort-indicator]`,
  `[data-dk-search]` + `[data-dk-spinner]`, `[data-dk-pagination]` / `[data-dk-page]`,
  `[data-invalid]` / `[aria-invalid]` / `[data-dk-invalid-marker]`, and the semantic elements.
- Every rule inside `:where(...)`: zero specificity, so any consumer rule wins without `!important`.
- Theming through `--dk-*` custom properties on `[data-datakable]`; a dark set under
  `prefers-color-scheme: dark`; no animation or transition under `prefers-reduced-motion: reduce`.
- Small: minified in the build; raw + gzip bytes reported.

## Packaging

- `@datakable/react`: tsup builds `src/styles.css` to `dist/styles.css` (minified). Exports
  `./styles.css`; `sideEffects: ["./dist/styles.css"]` (JS stays side-effect free).
- `datakable`: `src/styles.css` re-exports `@datakable/react/styles.css` (bundled by tsup into
  `dist/styles.css`, so the consumer resolves one plain file). Exports `./styles.css`;
  `sideEffects` adds `./dist/styles.css`.

## Tests (first)

- `packages/react/src/styles.test.tsx`: every attribute selector in `styles.css` names a hook
  (attribute + value) that `<DataTable />` actually renders across the scenarios (rows with sort /
  search / pagination / flagged rows, loading, empty, load error); every rule is wrapped in
  `:where`; the dark and reduced-motion blocks exist; both packages export `./styles.css` and list
  it in `sideEffects`; nothing in the JS sources imports CSS.
- `scripts/check-styles.mjs` (run by `pnpm check:pkg`, after build): esbuild bundles a consumer
  that imports `datakable/styles.css` (resolves through exports, output CSS non-empty and contains
  `[data-datakable]`), and a JS-only consumer of `DataTable` whose metafile has no `.css` input and
  no `.css` output. Prints raw + gzip bytes.

## Out of scope

- Any markup or attribute change in the components (T34 edits `data-table.tsx` in parallel).
- Class-based dark mode switches, density / size variants, CSS for user `components` overrides.
- Size-limit budget entry for the CSS (T37 owns budgets/CI).
- Docs playground usage (T39).
