# T36 — Packaging: per-feature entries, prod stripping, `datakable/messages`, type-leak check

Spec §12, §8.2, §9.1 (bundle), §9.3 (budgets). Measure gzip after each step (esbuild 0.27.7 and
rolldown 1.2.13; minify, `NODE_ENV=production`, ex-search / exsorted / kk-debounce external,
`gzip -9`): core `createTable`; core `createTable` + columnFilters + sorting + pagination;
`datakable` `createTable` (react external).

## Steps

1. **One dist file per source module** (tsup + `scripts/preserve-modules.mjs` esbuild plugin).
   The single-file dist defeated `sideEffects: false`: every top-level `defineDiagnostic` call and
   everything it references stayed in every consumer bundle.
2. **Prod stripping of message text.** `problem` / `impact` / `fix` move into one
   `<module>Messages` object per codes module; definitions get them as `DEV && xMessages.DK_X`
   (`defineDiagnostic(meta, text)` overload). The build writes `DEV` out as
   `process.env.NODE_ENV !== "production"` at every use, because esbuild only drops what a
   condition guards when it folds while parsing the module (an imported `DEV` folds too late).
3. **Registration that survives tree shaking.** `void xDiagnostics` keep-alives are dropped by
   bundlers with per-module dist, so emitted codes became unknown. Replace them with
   `keepDiagnostics(xDiagnostics)`. `check:catalog` gains a consumer-bundle check: per import
   scenario and per entry point, bundle (prod + dev), run, and require every emitted code to be
   defined (and to carry text in dev).
4. **`@datakable/core/messages` + `datakable/messages`**: installs all message objects so
   production diagnostics have full text again (`sideEffects` exception for these files).
5. **Per-feature entries** `@datakable/core/{column-filters,validity,search,sorting,pagination}`
   (+ publint / attw).
6. **Type-leak consumer check**: a tiny consumer project compiled with `skipLibCheck: false`
   against the built `.d.ts` of all packages.
7. Re-measure; if §9.3 is not met, report what remains and why.
