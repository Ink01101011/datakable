# T37 plan — §9.3 budgets in CI

Done when: every §9.3 budget is measured in CI; a budget the code does not meet is raised with the
user, never raised in the spec silently.

## Design

1. **Size** — one committed method (R10 standard), `scripts/size.mjs` + `scripts/size-limits.mjs`:
   esbuild 0.27.7 `bundle + minify + esm`, `NODE_ENV=production`, externals `ex-search`,
   `exsorted*`, `kk-debounce*`, `react`, `react-dom`; entry = one-line re-export from the built
   dist; gzip level 9 (Node zlib, as size-limit's file plugin). Six entries (core createTable;
   +columnFilters+sorting+pagination; +search; datakable createTable / useDataTable / DataTable),
   each with the §9.3 spec budget and a ratchet = measured size rounded up to the next 0.5 KB.
   `pnpm size` prints size / ratchet / spec; `pnpm check:size` fails on ratchet growth only.
   (size-limit 14's esbuild plugin needs esbuild ^0.28, so it cannot run the pinned method.)
2. **React dist** — one file per module (core's `preserveModules` plugin, `.tsx` aware), so a
   hook-only import drops `data-table.js` and its top-level `keepDiagnostics(...)`.
3. **Memory** — `pipeline/memory.test.ts` → `memory.gc.test.ts` in its own vitest project
   (`core-memory`, forks pool, `--expose-gc`). New `budgets/memory.budget.test.ts` on dist with
   the real default preset: filter+sort paginated (≤ 5 MB, enforced), client search and
   unpaginated (recorded, ratchet; spec unmet → user).
4. **Batch overhead** — `budgets/batch-overhead.budget.test.ts`: the column cache's batch built
   from the public pieces vs a raw loop over the same rows, fastest of 30 interleaved rounds,
   ≤ +10% enforced.
5. **Interaction / long task** — `budgets/interaction.budget.test.ts` (happy-dom = browser phase,
   slicing on): 4x throttle emulated by a 4x-fast `performance.now()`; tasks delimited at
   `scheduler.yield()` and at the commit (T29's method). 100k projection and string sort: longest
   task ≤ 50 ms (enforced). 10k type / sort / page: response < 100 ms (enforced); total CPU time
   printed and compared with 100 ms.
6. **Wiring** — `pnpm check:budgets` (size ratchets + budgets vitest config, after build); CI step
   after `check:pkg`.

## Out of scope

- Changing any spec budget, or code changes to meet them (core 23 KB vs 8 KB, preset 35–39 KB vs
  20 KB, search memory 16.4 MB vs 5 MB): pending the user's decision.
- The `"use client"` split for `datakable` (client entry vs root): a packaging decision for the
  user; T37 keeps the banner behaviour as is (every react module carries it).
- Making `vitest bench` files runnable from a script; release.yml.
