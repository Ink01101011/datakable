# T38 plan — `docs/errors.md` + catalog CI test

Spec §8.3, §11. Branch `feat/core-T38` from develop `a333e6b`.

## Approach

1. **Fault-test map shared** (`packages/core/src/fault-injection/injected-by.ts`, excluded from the
   build): the core catalog test keeps its assertions on it; react-registered codes
   (`DK_RENDER_FAILED`, `DK_UNSTABLE_*`) get entries pointing at react tests.
2. **`docs/errors.md`**: one `### DK_*` section per code (anchor = `code.toLowerCase()`, the URL
   `diagnostics/build.ts` builds), each with problem / common causes / fix / example, plus reading,
   sinks, production, redaction, `explain()` and plugin-author notes.
3. **Real examples**: one runnable file per code in `packages/datakable/src/errors-examples/`
   (typechecked against the built packages, run by the test, its printed console output compared
   with the page). Codes no snippet can trigger use a fixture built from their fault test's details
   (`errors-doc-fixtures.ts`). Server-render examples (`*.server.tsx`) run in a node-env test.
4. **Catalog CI** (`packages/datakable/src/errors-doc.test.tsx`): codes from the real registries
   (`datakable` loads core + react); fails on a code without a section, anchor, parts, level, fault
   test link/entry, example, or a non-empty `where` / `fix` in its real diagnostic.
5. **Dist registration** for `@datakable/react` (`scripts/check-catalog.mjs`, in `check:pkg`),
   like core's `check:catalog` (T24 carry-over).
6. Carry-over code items, test-first: schema issue → column mapping by segments (R7); production
   console prints thrown errors by name only (R2); README status example matches `<DataTable />`'s
   Loading rule (R10); tighter JSDoc-once assertion (T10, optional).
7. Spec: §8.1 Location kinds, §8.3 table lists every registered code, §3.4 tracer wording (T25).

## Out of scope

- Changing diagnostic texts or levels (the page documents what the code prints).
- Printing `context.cause` in the dev console group (R2 optional): the console is a sink governed by
  redaction, and the cause can carry row values; `onDiagnostic` already receives it.
- A dev Proxy for production `createApi` failures (documented: a plain `TypeError` in production).
- The open status-rule question (`inStepDiagnosticSetsError`, T30): documented as current behaviour.
- Performance budgets (spec §9.3 unmet budgets are tracked elsewhere).
