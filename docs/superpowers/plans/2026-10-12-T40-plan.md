# T40 — READMEs + first changeset (plan)

Spec §12. Done when the READMEs describe the real API on `develop` and one changeset is added.

## Approach

1. **Examples are code first.** Every TypeScript block in a README is a file under
   `packages/datakable/src/readme-examples/` (one file per block, so each keeps its own imports
   verbatim). They are part of the `datakable` package's `tsc -p` (`pnpm typecheck`), which
   resolves `datakable`, `@datakable/core`, `@datakable/core/<feature>`, `@datakable/core/messages`
   and `@datakable/react` through the built packages — exactly what a consumer sees. They are not
   tsup entries, so they never ship.
2. **Drift test** (`readme-examples.test.ts`, vitest): every ` ```ts ` / ` ```tsx ` block in the
   repo README and the three package READMEs must be byte-equal (after trimming) to one example
   file, and every example file must be used by a README. A README edit that is not compiled fails
   the gate.
3. **READMEs**
   - root `README.md`: what DataKable is, packages table, quick start, links to the package READMEs,
     the bundler / `NODE_ENV` requirement; keeps the existing development / releasing sections.
   - `packages/datakable/README.md`: install, zero-config `useDataTable` / `createTable`, features,
     status model, diagnostics in short, `datakable/core`, `datakable/messages`.
   - `packages/core/README.md`: full headless reference — `createTable` (bare: no preset),
     `defaultFeatures`, per-feature entries, columns, schema / `invalidRows`, server mode + fetcher
     + `refetch`, row model + status + `isInitialLoad`, diagnostics + redaction + messages,
     `explain` / `explainRow`, `NODE_ENV`.
   - `packages/react/README.md`: `useDataTable` (bare), option sync rules, render-loop guidance,
     status-driven UI.
4. **Changeset**: one file, `minor` for the three packages of the fixed group (0.0.0 → 0.1.0).

## Out of scope

- `<DataTable />` (T33) and SSR `initialState` / `initialData` (T32) are not on `develop`: they are
  described in prose only, marked "lands with T33 / T32", with no compiled example. The reviewer
  reconciles after merge.
- `docs/errors.md` (T38) — READMEs link to it as the docs URL diagnostics already carry.
- `styles.css` (T35), playground (T39), any source change, `changeset version` / publish / tag.
