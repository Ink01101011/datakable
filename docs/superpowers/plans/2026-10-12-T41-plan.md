## The six common errors

From §4.1 "6 invalid cases error": (1) typo key, (2) nested typo, (3) `range` filter on a string,
(4) object column without `cell` / `format`, (5) function column without `cell` / `format`,

## How messages are pinned

`@ts-expect-error` alone only proves *an* error exists. To pin the text:

1. `type-errors.test-d.ts` is the single source of the cases. Vitest typecheck (and `pnpm
   typecheck`) prove every marked line errors.
2. `type-errors.test.ts` (a normal vitest unit test) reads that file, blanks out the
   `@ts-expect-error` directives (same length, so positions stay put), compiles it in memory with
   the TypeScript compiler API using `packages/core/tsconfig.json`, and maps each diagnostic back
   to its `[E<n>]` marker. It asserts the TS error code and key fragments of the flattened
   message (e.g. `Did you mean '"first"'?`, `required in type 'NeedsFormat<`). A TypeScript upgrade
   that rewords these fails the test.
3. The same test asks the language service for quick info on `cell` / `format` and asserts the
   JSDoc text appears — the automated "shows on hover" check.

Fragments, not full strings: the full text contains the whole `Path<User>` union, whose member
order is a TypeScript implementation detail.
