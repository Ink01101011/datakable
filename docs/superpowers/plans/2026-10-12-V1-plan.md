# V1 plan — version 1.0.0, docs hub skeleton, docs drift + link tests

Job datakable-docs-v1, unit V1 (implementer). Branch `feat/core-V1` from develop 93a9b70.

## Steps

1. **Tests first** (`packages/datakable/src/`):
   - `docs-check.ts` — test-only helpers: list `docs/**/*.md` (minus `docs/superpowers/**`), parse
     fenced blocks, GitHub heading slugs (with `-1`, `-2` for duplicates), link extraction.
   - `docs-examples.test.ts` — drift test. Page `docs/<path>.md` ↔ folder
     `src/docs-examples/<path>/`. The n-th ```ts / ```tsx block of the page is the file
     `<n>-<slug>.ts(x)` (block text == file text, extension == block language, files numbered
     1..N with no gaps). Every file in `docs-examples/` belongs to a page block; `_`-prefixed files /
     folders are unshown helpers. ```typescript fences and indented ```ts fences fail (they would
     escape the check). Pages verified by their own test are skipped: any `errors.md`
     (`errors-doc.test.tsx`), and the legacy `docs/reading-type-errors.md` (type-error fragments;
     D3 rewrites them as compiled examples when it moves the page).
   - `docs-links.test.ts` — every relative link (inline and reference style, outside code fences)
     in `docs/**/*.md` (minus superpowers) and the four READMEs resolves to an existing file or
     folder, and its `#anchor` to a heading (GitHub slug rules) or `<a id/name>` of the target
     `.md`. Absolute `https://github.com/Ink01101011/datakable/(blob|tree)/main/…` links are
     checked the same way against the working tree. Every docs page is reachable from
     `docs/README.md`.
   - `pnpm typecheck` already compiles `packages/datakable/src/**` (tsconfig `include: ["src"]`),
     so `docs-examples/**` is compiled with no config change; verified with a deliberate error.
2. **Docs hub**: `docs/README.md` (what DataKable is, the three sections, start-here path,
   contributing note), `docs/how-to-use/README.md`, `docs/examples/README.md`,
   `docs/how-to-fix/README.md` (purpose + "pages coming" list, no broken links). Hub linked from
   the root README (relative) and each package README (absolute GitHub URL, as those READMEs do
   for npm).
3. **Version 1.0.0**: `.changeset/initial-release.md` → `major` for the three fixed packages, text
   no longer pre-release; remove the "Pre-release (0.x)" notes from the four READMEs. Check spec
   and source for 0.x wording / hard-coded versions (`normalize(<version>)`, `VERSION`,
   `DK_FEATURE_INCOMPATIBLE` `^2.0.0`).
4. Gate: `pnpm lint && pnpm build && pnpm typecheck && pnpm test && pnpm check:pkg &&
   pnpm check:budgets`; `pnpm changeset status`.

## Out of scope

- Running `changeset version` / publish / tagging (the user releases).
- Writing guide, example or troubleshooting pages (D1, D2, D3), moving `docs/errors.md` /
  `docs/reading-type-errors.md` (D3), reconciling the hub's page list (RD).
- Verifying ```text output blocks of new pages (each D unit does it like `errors-doc.test.tsx`).
- Any library behaviour change.
